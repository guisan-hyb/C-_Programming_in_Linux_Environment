# 08 · 从零复刻：分阶段任务与自检

1. **每个阶段都要能跑起来、能验收**，不要一口气写完再看效果；
2. **先自己想，卡住超过 20 分钟再翻原码**；翻完把"自己当时的想法"记下来，这是最有价值的产出；
3. **不要让编译器替你想问题**：`-Wall -Wextra` 一直开着；
4. 每个阶段结束把代码发我，我按下面列的点 review（正确性/边界/并发/资源/风格）。

阶段路线（每一阶段都建立在前一阶段之上，**都是能编译能跑的**）：

## 阶段 1 · 阻塞式 echo 服务器（约 60 行）

**目标**：只做一件事 —— 一次连接，读多少回多少，不涉及任何协议解析和 epoll。

```cpp
// 目标骨架（自己补全，不要抄）
int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
setsockopt(SO_REUSEADDR);
bind();  listen();
while (true) {
    int c = accept(...);
    char buf[4096];
    ssize_t n = read(c, buf, sizeof(buf));
    if (n > 0) write(c, buf, n);       // 先假设一次 read 就能读完
    if (n <= 0) close(c);
}
```

**要亲手验证的坑**

- `SO_REUSEADDR` 不加会怎样？（重启服务端 `bind: Address already in use`）
- 客户端 `close()` 之后 `read` 返回什么？（返回 0）
- `sockaddr_in` 里的 `sin_port` 为什么必须 `htons`？（自己试一次不转的后果）

**验收**

- [ ] `nc`（或 `echo_client.py echo`）能收到回显
- [ ] 能在服务端打印出客户端 IP:端口

**我会 review 的点**：错误检查是否每个系统调用都做了；`SOMAXCONN` 是否用了；`close` 是否漏。

## 阶段 2 · 协议拆包（仍然阻塞）

**目标**：把 4 字节头 + `body_len` 的协议做出来，**在阻塞 IO 下**把"半包"、"粘包"处理对。这一阶段是整个项目最核心的逻辑，值得慢慢磨。

建议的写法（阻塞版反而更简单，因为 `read` 会等）：

```cpp
bool read_exact(int fd, char* buf, size_t len);   // 循环 read 到读满，返回 false 表示对端关闭

while (true) {
    char head[4];
    if (!read_exact(c, head, 4)) break;
    uint16_t type, blen;
    memcpy(&type, head, 2);  memcpy(&blen, head + 2, 2);
    type = ntohs(type);      blen = ntohs(blen);
    if (blen > BUFF_SIZE) break;                  // 长度校验
    std::string body(blen, '\0');
    if (!read_exact(c, body.data(), blen)) break;
    write_all(c, pack(type, body));               // 回显（含头）
}
```

**这一阶段必须想清楚的三个问题**（想清楚再写，别边写边试）

1. `read_exact` 里 `read` 返回 0 / EINTR 分别怎么处理？
2. `blen == 0` 的包怎么处理？（回想 [06 章 D1](06-生命周期、错误处理与已知缺陷.md)：原版在这里翻车了）
3. 为什么阻塞版可以不写状态机，而非阻塞版必须写？（提示：阻塞版的状态保存在"函数正在执行"这件事本身，也就是保存在线程栈上）

**验收**

- [ ] `echo_client.py echo / split / split-head / sticky` 四个用例都过
- [ ] `echo_client.py zero` 在你的实现里是"正常回显空包"而不是断连（你已经修掉了 D1）
- [ ] `echo_client.py oversize` 时服务端主动断开

**我会 review 的点**：`memcpy` 而不是指针强转；长度校验；大端转换是否成对出现；`std::string` 存二进制时用 `data()/size()` 而不是 `c_str()`。

## 阶段 3 · 非阻塞 + 单线程 epoll + ET

**目标**：把阶段 2 的阻塞 IO 改成 **非阻塞 + epoll（ET）**，把"等数据"这件事从"阻塞在 read 里"改成"由事件通知"。

改造步骤（顺序很重要，每一步都要能编译）

1. `set_nonblocking(listen_fd)`；
2. 把"每个连接一个阻塞循环"改成 **状态机**：`NO_RECV / HEAD_RECVING / BODY_RECVING`（这就是原版 `Session` 干的事）；
3. `epoll_create1` + 注册 `listen_fd`（`EPOLLIN|EPOLLET`）；
4. `accept` 循环到 `EAGAIN`；连接注册进 epoll；
5. 收到 `EPOLLIN` 后**循环 read 直到 `EAGAIN`**。

**必须自己踩的坑（建议故意踩一次，再修）**

1. `read` 只调一次就退出 `EPOLLIN` 处理 → 用 `sticky` 用例能复现"丢包"；
2. `accept` 只调一次 → 用并发连接测试能复现"漏连接"；
3. 忘记 `set_nonblocking` 就注册 epoll → 某个客户端只发半个包时**整个进程卡死**（这是最值得亲身体会的一次故障）；
4. 把 ET 换成 LT 再跑一遍 `sticky`，观察行为差异。

**验收**

- [ ] 阶段 2 的 4 个用例全过
- [ ] 用"故意踩坑"的版本复现故障，并能解释每个故障的原因
- [ ] `strace` 里能看到稳定的"read → read → EAGAIN → epoll_wait"节奏

**我会 review 的点**：返回码设计（读到一半 vs 读空了怎么表达）；状态复位的集中性（建议写 `reset_recv_state()`）；`EPOLLERR/EPOLLHUP` 处理。

## 阶段 4 · 发送队列与 EPOLLOUT

**目标**：让"写不进去"变成可恢复的状态，而不是丢数据或断开连接。

改造点

1. 每个连接一个发送队列 `std::queue<std::shared_ptr<DataBuf>>`，每个 `DataBuf` 带 `_offset`；
2. `send_data()`：入队 → 循环写 → `EAGAIN` 时**保留节点和 offset** 并返回"需要等可写"；
3. 调用方收到"需要等可写"→ `epoll_ctl(MOD, EPOLLIN|EPOLLOUT|EPOLLET)`；
4. `handle_epollout()`：从队首续写；发空后 **`MOD` 摘掉 EPOLLOUT**。

**故意踩坑清单**

1. `EAGAIN` 时把数据丢弃 → `flood` 用例下客户端收到的字节数变少；
2. 忘了摘 EPOLLOUT（用 **LT** 版本试）→ 服务端单核 100% CPU；
3. `write` 返回 0 时不处理 → 对端关闭后死循环或数据丢失；
4. 用 `while (write(...) > 0)` 一次写完 → 部分写场景下丢尾部数据。

**验收**

- [ ] `echo_client.py flood` 全部回显（字节数一致），服务端 CPU 正常
- [ ] `echo_client.py flood` 期间服务端不崩、不 OOM
- [ ] 能解释"EPOLLOUT 为什么要按需订阅"

**我会 review 的点**：`Defer` 用法与 `_send_stage` 的复位；出队/续写的边界；错误路径是否统一走"清理连接"函数。另外注意 [04 章附录](04-发送链路：发送队列与部分写.md) 里那个"死分支"——你的实现不要用 `_send_stage` 表达"还有数据没发完"，直接用队列判断。

## 阶段 5 · 多线程：eventfd + 任务队列 + 线程池

**目标**：把单线程 Reactor 变成 `1 个 acceptor + N 个 IO 线程`。

设计顺序（先设计再写代码）

1. 定义 **跨线程通信的消息**（本项目的 `IOTask`：`RegisterConn / SendData / Shutdown`）；
2. 每个 IO 线程：自己的 `epoll_fd` + `event_fd` + `任务队列 + mutex`；
3. `wakeup()`：往 eventfd 写 1；
4. `deal_enque_tasks()`：用 `swap` 换出整个队列再处理（锁持有时间最小化）；
5. 主线程：`accept` → 按 `fd % N` 分发 → 批量入队 → 每个涉及到的线程只唤醒一次；
6. 连接的创建、非阻塞设置、epoll 注册，**全部在目标线程内完成**（保证不变量 A）。

**验收**

- [ ] `echo_client.py echo -n 16` 16 条连接全部正常
- [ ] `ps -T` 能看到 1 + N 个线程；`top -H` 看线程 CPU 分布（应该比较均匀）
- [ ] 故意删掉 `wakeup()`：能复现"新连接卡住不处理"，并能解释为什么
- [ ] 你能一句话说清：为什么 `Session` 里一把锁都不需要？

**我会 review 的点**：`_tasks` 的锁范围；是否存在"忘记唤醒"的路径；`_sessions` 是否只被 owner 线程访问；线程创建/启动顺序；`std::atomic<bool> _stop` 的可见性。

## 与原版的差异对照清单（建议逐条自己判断）

复刻完成后，拿你的代码和原版对比，逐条问自己"哪个更好、为什么"：

| 主题 | 原版做法 | 你可以考虑的做法 |
| --- | --- | --- |
| "还有数据没发完"的判断 | `_send_stage == SENDING`（死分支） | `!_send_que.empty()` |
| 空包体 | 会被当成对端关闭 → 断连 | 当作正常包回显 |
| `body_len` 校验 | `> BUFF_SIZE` 断开 | 同上 + 记录日志/统计 |

## 进阶改造题（按难度排序，做完一个就算一个里程碑）

1. **优雅关闭**：`shutdown(SHUT_WR)` 后再关，保证 `_send_que` 里的数据发完再断开。
2. **心跳与超时**：`epoll_wait` 改成有时限，用最小堆管理空闲连接，超时踢掉。
3. **write 缓冲合并**：把队列里多个小包合并成一次 `writev`，减少系统调用（对照 `SYN` 写放大问题）。
4. **缓冲区复用**：用对象池 / 环形缓冲替代每次 `malloc`，观察 `perf` 变化。
5. **主从 Reactor**：把 acceptor 也改成多个线程（`SO_REUSEPORT`），对比 Nginx 的多进程模型。
6. **业务线程池**：IO 线程只做收发，业务丢给 worker 池，学会"把 CPU 密集和 IO 分离"。
7. **协议扩展**：把长度改成 4 字节、加序列号/校验和，实现自动重传与去重。
8. **单元测试**：给拆包状态机写不依赖 socket 的纯函数测试（把协议解析从 `Session` 里解耦出来）。
